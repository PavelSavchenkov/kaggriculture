# Second prospective wave — draft until the freeze manifest exists

The next gate uses holdout_a, which is still unopened. Downloading is allowed only after the export checks and `snapshots/search_wave_v2/FREEZE.json` have been written. This file is the planned protocol, not evidence that a candidate passed.

Candidate components: the direct-cost extra-tree estimator from `cost_model_study_v3`, the necessary output/action and carried-input bounds, and the float32-canonical query-success models from `query_layout_study_v2`. These fits use the exposed development families only. The cost predictor estimates a reference bill; it does not certify a workforce. The optional query predictor estimates success of a specific three-second root compiler call; it does not classify physical feasibility.

Primary practical comparison: direct-cost ordering with nearby-workforce queries and analytical/dominated-cost pruning, against the original geometry estimator with the same query-order/pruning improvements. Retain the original flat10 and literal sequential-query baselines. This compares the estimator under a common cold backend. It does not reproduce the old source-visit reuse, fixed repair, inherited hire calendars, economic forecast or complete course compiler.

Optional hard-case treatment: begin with the cheap ordering; after the first observed compiler failure, use boosted success probability times possible hire-cost improvement to order the remaining calls. The nominal three-second budget is the primary denominator. Predicting CPU is a secondary alternative. A completed failure may trigger the outer search policy; neither pure predictor receives schedules or candidate solver outcomes as a feature, and neither invokes the solver internally.

Data: four most recent completed player-games from each of the eight preassigned holdout_a teams' best-public-score submissions, selected before inspecting replay content. Verify all replay transitions and extract only the selected seats. Build six layout pools and six whole-asset work-subset pools per family using the previously implemented hash rules. Identity, near/far geometry and removal-size controls remain present. Layouts preserve work/output/non-labor value; changed-work pairs are evaluated for signed marginal cost, not ranked as if their product value were identical.

Query range: every supported worker count from the physical task-only capacity bound through 40, independent of source workforce. Additional necessary bounds may prune calls within this range. The full range is a reference design, not a prediction feature. Use the same frozen ordinary-day reference binary and three-second calls. Preserve every outcome, actual CPU time and strict certificate. UNKNOWN remains budget-limited failure, not infeasibility. Source certificates and later adjudication may tighten physical upper bounds without changing the short-compiler results.

Freeze all cost and query predictions before consulting the new solve outcomes. Audit exact physical overlap with every exposed source, layout, subset and synthetic contract; retain both full-wave and truly novel results. Exclude an overlapping parent from the primary novel-pool analysis. Whole-team separation does not prove independent authorship or strategy ancestry.

Primary measures: time to the best known short-compiler certificate; best verified hire cost and no-certificate rate at 3, 10, 30, 60, 120 and 240 CPU seconds; prediction time including physical feature extraction; conditional query-model use; and total scoring-plus-compilation CPU. Report source and marginal signed errors, expensive underestimates, overestimates, family slices, workload/geometry/input-release slices and unresolved reference intervals. Bootstrap by family, retaining per-pool regressions.

Acceptance for this scoped cold component: at least 20% lower mean time to best reference cost than original geometry with nearby-worker ordering, positive family-bootstrap lower bound on saved time, and no worse 30-second mean verified cost or certificate rate. The optional query model needs at least 5% mean time improvement over direct-cost nearby ordering, or a clear fixed-budget cost/certificate benefit without more than 5% mean time regression. Report uncertainty; a development win or a point estimate alone is insufficient. Parity must pass without weakening the 1e-7 mixed absolute/relative numerical tolerance. Prediction cost is measured and included, with no universal per-case latency cap.

This exported query model supports ordinary 24-phase contracts. Terminal 23-phase reference evidence remains a separate support task; the final reusable estimator must either support that horizon with its own tested path or identify it explicitly as unsupported. Do not pad terminal work into phase 23. Mid-day state, cash, capacity and full-game value remain outside the initial physical contract.

Keep holdout_b unopened. After this wave is reported, it may become development evidence for a later version that requires fresh testing.
